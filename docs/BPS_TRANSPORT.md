# BPS 传输与对照测试

## 选择传输

设置 → 连接与维护 → BPS 上游传输，显式选择 HTTP / SSE 或 WebSocket。已有配置继续使用 HTTP；WebSocket 是实验选项，不会在失败时切换传输或重放请求。客户端仍使用本机 `/v1/responses`，无需具备 WebSocket 能力。

WebSocket 使用同一账号、工作区、代理和请求转换器。图片先经现有附件接口上传，客户端函数和自由格式工具沿用现有桥接协议。新连接生成独立请求标识；不会复用抓包中的 Cookie、门票或恢复令牌。控制事件不传给客户端；断流、超时、排空或无完成事件不会记为成功。

若首个上游事件已是失败，本地流式和非流式 API 都返回 HTTP 502，记录 `stream_status: failed`；上游握手的 HTTP 200 不代表生成成功。已经向客户端开始输出的 SSE 通过失败终止事件表达中断。

## 独立 BPS 授权

从 `0.9.0-bps-preview.5` 开始，账号页的 **授权登录** 默认提供账密与 2FA 协议导入。选择 **Codex 原生授权** 或 **BPS 授权**，按 `邮箱----密码----2FA种子` 每行粘贴一个子号；未开启 2FA 时留空最后一段，单次最多 50 个。每个账号创建独立 HTTP 会话，不打开浏览器，不读取已有浏览器 Cookie。多个工作区需要明确选择。

BPS 协议在密码与 MFA 验证、工作区选择后提交本次设备批准；仍要等待后端完成 device poll、PKCE 兑换、邮箱/client 校验和保存，才显示已就绪。成功项可点击 **使用此账号**，同步选择账号和对应通道。失败项不会导致后续账号被丢弃；支持跳过当前账号、取消全部及关闭面板取消。

输入框默认隐藏资料，开始后清空；密码和种子只在本次进程内使用，不写入账号库、日志或命令行参数。HTTP 辅助进程通过私有标准输入/输出传输数据，任务结束关闭。已有代理设置同样用于协议登录；不会在代理失败后自动直连。

遇到手机号、额外邮箱验证或未支持的挑战步骤时，显示对应原因并停止该账号。可以重新选择 **浏览器自动授权（备用）**，或通过 **手动浏览器授权** 使用 preview.4 的设备码流程；不会在后台自动降级为浏览器。原有 JSON 粘贴/文件导入不变。

2026-11-12 在 Windows 上，两名子号的原生与 BPS 协议授权均实测入库；其中同成员/工作区的原始糖果题在两通道均结论为 21。并未据此证明所有网络、挑战类型和账号均可自动授权，也未测试暂停中的母号。

同一成员、同一工作区的 BPS 与 Codex 授权分别保存，账号卡片和测智列表显示授权类型。不会用一次 BPS 登录覆盖原生凭据，也不会在选择原生通道时自动改用另一条账号记录。导入支持从 token 中识别 OAuth client，以及显式的 `oauth_client_id` 或 `type: "bps"`；只有 refresh token 的旧 Codex 导入格式仍兼容。

BPS 使用独立设备授权、PKCE 校验和对应 client 的令牌刷新。刷新返回不同成员、工作区或 client 时拒绝替换；刷新失败后不自动重放该 refresh grant，需重新授权。浏览器打开地址受限，凭据不会通过 IPC 或管理响应返回渲染器。

拥有 Codex 授权不代表拥有 BPS 生成权限。401/403 保留为认证或访问错误，不作为模型能力结论。本轮真实生成验证使用独立 BPS 授权和显式 WebSocket；没有据此宣布所有账号、HTTP 传输或长期批量使用均已验证。

## 直连验证（2026-11-12）

通过本项目本地 API 直接访问 BPS WebSocket，模型选择 `gpt-6-astra / medium`，得到以下结果：

| 项目 | 实际观察 |
| --- | --- |
| 独立登录及刷新 | 浏览器设备授权完成并保存；一次真实 BPS 刷新成功 |
| `hi` | 生成完成；22,828 输入、22,825 缓存输入、13 输出 tokens；响应中的 instructions 为 61,468 字符 |
| 原始糖果题 | 9 个测试账号，逐账号原生/BPS 对照；两条通道均给出 21，并使用按形状选择的条件 |
| 函数调用及结果回传 | 模型先调用 `read_fixture`，再调用 `write_result`；客户端实际写入随机标记和求和结果 111，最终回复与文件一致 |
| 图片 | 正确识别蓝色圆形、橙色方形和测试字符；23,037 输入、22 输出 tokens |
| 原始鹈鹕题 | 原生与 BPS 均生成可渲染 HTML/SVG；隔离预览中均出现鹈鹕骑车，动画画面随时间变化，无页面错误 |

对照固定原始题目、模型和 medium 档位，核对同一成员与工作区，使用各自独立授权。部分回答补充“不允许选择形状时为 29”，或在证明中出现其他“至少”数量；自动解析保留为待复核，阅读原始回答后确认其本题结论为 21。没有把待复核自动算成错误，也没有向上游发送预期答案。

**本轮证明了直连 BPS API 可以生成、看图并完成实际工具往返；尚未观察到同账号“原生答错、BPS 答对”。** 因此不能把这些结果表述为已证明恢复下降的能力。鹈鹕的渲染与动作检查也不等同于证明内部模型权重或完整 Codex 长任务可靠性。

经授权测试的一条外部 Responses 中转，在 `gpt-6-astra / medium` 下得到：

| --- | ---: | ---: | ---: | --- |
| `hi`，无 instructions | 18,365 | 18,362 | 11 | 完整回答；返回约 21,260 字符的 Codex 通用指令 |
| `hi`，30 字符 instructions | 14,260 | 0 | 11 | 调用方 instructions 原样保留；高输入量仍存在 |
| 原始糖果题 | 18,540 | 0 | 1,162 | 结论 21，并说明按形状选择的策略 |

| 函数调用及结果回传 | 14,439 / 14,513 | 0 / 0 | 20 / 21 | 调用声明的函数，使用返回的随机标记并正确求和 |
| 原始鹈鹕题 | 18,390 | 0 | 5,826 | 完整 HTML；隔离预览显示鹈鹕骑车，11 个运行中的动画 |

以上只证明该中转当时的外部行为。用户侧响应不能证明其内部一定使用 BPS、具体隐藏提示词或实际模型权重。可见 instructions 与本项目模型目录中的 Codex 基础指令相似但版本不同。短指令请求仍有约 14k 输入，不足以推断全部隐藏上下文内容；没有将这部分内容臆造为固定“焚诀”写入项目。

输入量、缓存命中和实际计费是不同指标。运行记录现分别保存总输入、缓存输入、输出和推理 tokens；缓存包含在输入量中。账单还受中转价格、倍率等影响。

## 怎样比较

1. 为同一成员和工作区分别完成 Codex 与 BPS 授权，固定模型与 medium 档位，再显式选择对应账号记录和传输。
2. 测智页使用未经改写的糖果题和鹈鹕题；预期答案只用于本地判定，不发给模型。
3. 保存完整回答、传输、报告模型、完成状态及用量。鹈鹕还应查看动作与画面；工具能力应检查实际调用和结果回传。
4. 自动解析为待复核时检查完整回答，特别是同时解释 21 和 29 对应条件的情况；不要把它当成答错。
5. 使用有明确对照差异的账号重复测试。健康账号单次通过、名字匹配或大量 tokens 都不能证明解决了能力下降。

模型名、状态头长度和 buffering 是协议观测字段；界面不再凭这些字段自动宣称“正常”或“降智”。桌面启动与测智固定账号和通道，不自动切换模型或推理档位来制造通过结果。

本地协议与授权测试：`go test ./internal/oauth ./internal/account ./internal/pool ./internal/upstream ./internal/router ./internal/server`。桌面测试：`npm --prefix desktop test`。
