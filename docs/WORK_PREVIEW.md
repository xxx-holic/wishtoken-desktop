# Work 通道本地预览

版本：`0.9.0-bps-preview.3`。此前本地 Work 预览现纳入源码更新；安装包发布状态以 Releases 为准。BPS 传输研究见 `BPS_TRANSPORT.md`。

## 开始测试

1. 启动新版 WishToken Desktop，沿用原账号数据。点击右上角“导入 JSON”，直接粘贴待测账号的单个对象或数组；也可切换“从文件导入”选择 JSON 文件。支持 `id_token`、`access_token`、`refresh_token`、`account_id`、`last_refresh`、`email`、`type` 和 `expired`。
2. 进入“设置 → Work 浏览器”，选择待测账号，点击“打开专用登录浏览器”。需要本机已安装 Chrome 或 Edge。
3. 在浏览器登录**同一邮箱、同一工作区**，进入 ChatGPT 的“工作”，选择 **GPT-6 Astra / 中**。回到客户端点击“登录完成，绑定”。账号 JSON 不能直接代替网页登录。
4. 已有专用调试浏览器也可展开“连接已有的专用调试浏览器”，读取标签页并明确选择绑定。默认地址为 `http://127.0.0.1:9222`。关闭该标签页或重启浏览器后可能需要重新绑定。
5. 进入“测智对比”，选择“糖果题”，先用**原生 Codex / GPT-6 Astra / medium**测试，再用**ChatGPT Work / GPT-6 Astra Work / medium**测试。使用同一账号，保留每轮结果。鹈鹕题也在这里切换。
6. Work 对外模型标识是 `gpt-6-astra-wm`；名称不同是入口目录的实际标识，不代表已经证明使用相同权重或更强的模型。

糖果题的预期值 21 只参与本地判定，完整题目原样发送，没有额外答案提示。界面区分“本题通过”“本题未通过”“待人工确认”；自动识别结论可能需要人工核对。改写题目后不套用原题答案。鹈鹕提示词也保持用户给定原文；生成的 HTML 不经过修复。

“完成请求”和“答案正确”分别记录：错误答案仍保留原文，不按网络失败丢弃。历史继续使用原有 `pelican/` 目录，旧鹈鹕历史可读。

## API 与工具

客户端原有的本地 API 地址和 Key 继续使用。Work 不需要另外手动启动 Python 服务。桌面主进程内置浏览器桥，Go 服务转发到仅监听回环地址、单独鉴权的内部入口。

```json
{
  "model": "gpt-6-astra-wm",
  "reasoning": {"effort": "medium"},
  "input": "你的任务",
  "stream": true
}
```

向 `/v1/responses` 发送此请求，使用本地 API Key，并通过 `X-GPTBridge-Account` 固定已绑定的本地账号 ID；可同时设置 `X-GPTBridge-Channel: work`。Codex 启动配置会自动固定这两个值。

- 支持 Responses 和经现有适配器转换的 Chat Completions。实时验证以 Responses 为主。
- 支持 JSON 参数的函数工具，由客户端执行。工具说明、角色与完整历史转换成文本协议；不等同于原生角色优先级或原生 function calling。
- 模型目录包含 7 个 Work 标识与 low–max 档位；浏览器所选模型和档位必须一致。此前真实测试覆盖 Astra Work / medium，其他组合尚未逐一完成真实生成验收。单个页面并发 1，不自动换号、换模型、换档位、换入口或重发。
- SSE 等待期间发送保活，回答结束后输出完整事件；不是逐 token 输出。上游不提供本地可用的加密推理或准确用量时不伪造。
- 完整文本提示词上限 180000 UTF-8 字节；不静默截断。新建 Work 启动配置建议上下文 32000、压缩阈值 24000。客户端需回传完整历史，不支持 `previous_response_id`。
- 支持文本、JSON 函数与命名自由格式工具。图像通过网页编辑器粘贴上传：完整历史最多 4 张，单张 6 MB、总计 16 MB；超过限制或工具结果内含图像会明确报错，不丢弃图像后继续。远程图片 URL、file_id 和其他二进制附件未实现。图像转换已有本地回归，网页上传仍受登录状态与上游变化影响。文本生成文件最多 4 个、单文件 1 MB，从同源已验证下载地址读取。
- 取消后不重新发送；已经提交到网页的请求可能继续执行，页面锁保持到完成或超时。应先检查网页任务再决定重试。
- 浏览器需保持登录，使用自身网络；此实现依赖网页，尚未验证长期稳定性或批量运行能力。

## 本轮验证范围

离线回归覆盖原题不泄露答案、错误结论保留、函数工具往返、SSE 成功/失败、账号/通道固定和旧功能。桌面窗口使用合成账号验证选择、判定、原文查看及隔离预览。

真实 Work 验证使用已授权的健康网页登录：糖果题返回 21；鹈鹕题取回完整 HTML；读取临时文件 → 写入计算结果 → 继续回答的三轮工具流程通过。原生 Codex 的完整终端操作能力、不同账号权限以及降智号效果仍以实际对照为准；健康号成功不能证明恢复。

本地测试命令：

```sh
python scripts/check-public.py
go vet ./...
go test ./...
cd desktop
npm test
node test/work-ui-smoke.cjs
node test/features-smoke.cjs
npm run pack:win -- --publish never
```

`test/work-live.cjs` 是显式启用的真实请求探针，需要通过环境变量 `WISHTOKEN_WORK_TEST_TARGET` 指定有权使用的独立 Work 标签页。它会消耗该账号额度，结果位于 Git 忽略的 `build/validation/`，不作为日常自动测试。
