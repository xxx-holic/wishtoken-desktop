# BPS → 原生（预热通道）

这是一个显式选择的分阶段流程。先使用独立 BPS 授权完成预热，再让 Codex 的正式请求走同账号原生授权。它与焚诀订阅通道相互独立。

## 使用

1. 通过现有协议授权或 JSON 导入，保存同账号的 **Codex 原生授权**和 **BPS 授权**。两者不能互换，邮箱、用户、工作区和代理必须相同。
2. 选择原生授权记录，服务通道选 **BPS → 原生（预热）**，点击 **配置 BPS 预热 / 查看进度**。缺少 BPS 授权时，可在面板中补充。
3. 默认发送 40 条 `hi`，可设为 1–100 条；若模型数超过设定总数，会至少覆盖每个可用模型一次。列表来自该账号的 BPS 实时准入接口，排除受限、未启用和不可用模型。模型明确不支持 low 时会停止。
4. BPS 阶段使用 `reasoning_effort=low`，省略 `service_tier`，每条间隔 2–5 秒。全部响应完整成功后，续期原生凭据；没有刷新令牌且现有原生凭据有效时复用现有凭据。
5. 显示 **预热完成** 后，可启动 Codex App / CLI，或选择此通道做测智。正式请求保留所选模型、推理强度、速度和内容，实际走原生。后续启动复用完成记录，不重复预热。

## 失败与恢复

- 401、403、网络错误、5xx 或不完整响应立即停止，不换账号、不切备用通道、不将失败算作成功。
- HTTP 429 和 HTTP 200 响应流内的 `rate_limit_exceeded` 都会暂停。优先使用 `Retry-After`；没有有效值时执行 90 秒本地退避。这不是上游额度恢复承诺。倒计时结束后可显式再尝试，重新预热也不能跳过等待。
- 预热面板显示授权配对、BPS 预热、原生就绪三个阶段及逐模型完成数。关闭后任务继续，启动面板仍显示后台进度；失败保留具体分类、模型和完成断点。
- `deviceauth_disabled` 会提示打开 ChatGPT 安全设置，启用设备代码登录后重新授权。程序不会静默修改账号安全设置。
- 已完成条数写入本地私有数据目录。取消或重启后可继续未完成部分；请求结果不明的当前条不计为成功。
- 原生续期失败时保留全部 BPS 进度，修复授权后继续；不会重新发送已完成的 BPS 请求。
- 授权身份、代理或模型计划改变后，需要重新预热。运行期间暂停两套记录的后台自动续期和额度探针；BPS 阶段自身按需续期 BPS，末尾单独续期原生。
- 模型未通过准入、Free 账号或缺少独立授权时不启动；不会跳过 BPS 直接交付原生。
- 预热会消耗 BPS 额度。预热成功只表示请求流程完成，不能证明“降智恢复”。改善效果仍需同账号、同模型、同推理强度、相同原题的真实前后对照。

## 验证

独立实现只使用 Go 标准库，未捆绑参考压缩包的运行环境、代理或配置。最小请求体和 UUID 向量与用户提供的参考函数离线比对。

```powershell
go test ./internal/basispoints ./internal/server -run 'TestPrimer|TestBPSNative' -count=1
npm --prefix desktop test
node desktop/test/bps-native-ui-smoke.cjs
```

界面测试使用明确标记的合成回执；真实 HTTP 时序、凭据配对、停止、续跑、原生续期和路由检查由本地模拟上游测试覆盖。未把这些测试当作真实账号的质量恢复证据。

### 2026-11-26 本地实测

- 同一个 Pro 样本完成了独立 BPS 授权与 40/40 预热。限流后人工续跑，未跳过模型、切换账号或使用备用通道。
- 选择 `bps_native` 后，原生 `gpt-6-astra / medium` 回答原始糖果题为 21，保留的预热前答案为 29；原始鹈鹕题生成了完整双轮自行车和可运行动画。这是该样本的改善观察，不代表全局或永久恢复。
- 通过本工具生成的隔离配置，当前 Codex App 内置运行时成功读取随机文件、使用 `apply_patch` 写入结果，并通过文件内容校验。测试使用的是 App 内置 0.171.0-alpha.13，不是系统 PATH 中的旧 npm CLI。
- 本机 npm CLI 0.146.0 在真实请求和固定工具响应测试中都出现写文件失败。同样的补丁和工作区权限下，App 内置运行时成功；未因此关闭沙箱或改动全局 Codex 配置。遇到该现象时应区分运行时写入故障与模型能力。
- 两个授权中的原生授权没有刷新令牌，本次复用有效访问凭据，没有发生原生续期。未验证长期、批量可用性。
